# Dimitris Mourchoutas — portfolio

A static portfolio for GitHub Pages. No build step is required.

## Local preview

Serve this directory over HTTP (for example, `python -m http.server 4174`) and open `http://localhost:4174`. The floating gallery uses JavaScript modules; opening `index.html` directly as a file retains standard project cards instead.

## Interactive features

- `experience.js`: GSAP entrance and scroll animations and accessible project dialogs. Project-detail copy is keyed by each card's `data-project` identifier; descriptions, images, and links are read from the HTML cards. Add new projects at the beginning of `.projects-grid` to keep newest entries first. Reordering cards preserves their matching detail content.
- `skills.js`: an aligned diamond-view Three.js developer stack beside four groups of boxed technologies. On arrival, GSAP expands the gaps upward from the bottom, carrying upper layers together so plates never pass through one another. Shader compilation starts before the section enters view. Category hover, focus, or selection highlights the matching layer; flat labels stay readable, including Tools. Python is marked as currently learning; other technologies have no learning badge. The layout stacks vertically on small screens, honors reduced motion, and provides a CSS illustration when WebGL is unavailable.
- `hero.js`: original code waterfall, pointer glow, and a typing line. Animations stop offscreen, when the page is hidden, or when reduced motion is enabled. Reduced-motion mode displays a stable role description.
- `gallery.js`: HTML project panels placed at distinct depths through Three.js CSS3DRenderer over the site's original background. A stable scattered composition varies horizontal position, height, and depth without visible rows. Additional cards receive spaced placements automatically; the count, gallery height, and camera framing adapt with no six-project limit. GSAP eases proximity tilt, forward movement, detail reveals, and camera parallax. Titles and screenshots remain visible. Keyboard focus reveals the same controls; a list-view switch and automatic mobile layout preserve standard project cards. The gallery itself does not require WebGL.
- `experience.css`: responsive layouts and the interactive visual layer over the original styles.
- `showcase.js`: real RaceConsole screenshots and an on-demand replay video, plus SanteCafeBar's local animated receipt printer. Its demo-print button only animates HTML; it has no ordering endpoint or printer connection. Switching media pauses/hides demos while preserving their state; explicit Reset or closing the project clears it.
- `receipt-tear.js`: SanteCafeBar prints onto a continuous strip: each new order feeds above the existing paper instead of replacing it, and clicks during printing queue further orders. Short pulls spring back; longer pulls detach the entire printed strip with a torn edge. Cut paper stays visible, can be dragged again or moved with arrow keys, and remains within the visible project window when resized. Enter/Space also tears the attached strip. Printing and cutting preserve all taken receipts until the project closes, which clears the queue, paper, captured pointers, animations and collection. Reduced-motion mode keeps the same interactions without feeding/settling animation. The print control and viewer close control remain accessible above the paper.
- `race-demo.js`: RaceConsole's interactive telemetry illustration. Hold the pedals or W/S (up/down), and drag the steering wheel or hold A/D (left/right). Includes automatic gears, 13,000 RPM lights, tyre temperatures, lap timing, reset, and touch/keyboard support. Once started, lap time includes stationary time. Compact desktop layouts keep readings and pedals together in short windows. All readings are simulated in memory. Inputs release on blur, and animation stops offscreen, when hidden, or when the viewer closes. No game connection, persistence, or telemetry transmission is involved.
- `retro-demo.js`: a miniature RetroByte storefront with illustrated sample products, quantity controls, a sliding cart, accurate totals, removal, and per-product limits. The cart fits the visible viewer, keeps its total visible, scrolls items separately, and contains keyboard focus until dismissed. Escape closes the cart before the project viewer; the original website screenshot remains available. Cart state stays in memory, resets when the project closes, and has no checkout or network connection.
- `garage-demo.js`: a local, role-based appointment demo based on the AutoService-Garage repository's PHP controllers. Customers book registered sample cars for repair/service; a free mechanic is assigned using the two-hour availability rule. Secretary/mechanic views record arrival or non-arrival. Mechanics add/edit/delete work entries with materials, duration, and cost, and the appointment total is the sum of those entries. A labelled preview clock demonstrates automatic completion of in-progress appointments at the end of their two-hour window, and cancellation of missed appointments. Customer cancellation is limited to Created appointments. There is no drag board, percentage completion, backend connection, account login, or persistent data. Reset and closing restore the initial sample state. Source files reviewed on 2026-10-21: `add_appointment.php`, `manage_appointments.php`, `assigned_appointments.php`, `my_appointments.php`, `manage_jobs.php`, `functions.php`, and role navigation in `includes/dash_sidebar.php`. Repository: https://github.com/DimitrisM42/AutoService-Garage.
- `contact.js`: floating contact cards with SVG connections, a staggered entrance, eased pointer tilt, and an email copy button with status feedback. Links remain available without JavaScript, with a simpler layout on small screens and reduced-motion support.
- `about.js`: staggered reveals and gentle pointer tilt for three personal project notes. The introduction and all notes remain readable without JavaScript and respect reduced motion.
- `script.js`: native section links preserve hash URLs and Back/Forward history. Focusable section targets let the skip link continue through the content. CSS handles smooth scrolling and reduced motion. Also progressively loads the secret journal.
- `secrets.js` / `secrets.css`: eight original Easter eggs, a keyboard-accessible journal with locked clues, session-only discovery progress, and compact unlock messages. Touch-only devices have six available discoveries. User wheel/touch scrolling is required for scroll discoveries; anchor navigation does not trigger them. The completed hunt reveals a link instead of redirecting automatically. `secret.html` is the redesigned reward page. Progress is functional browser state and is disclosed in `privacy.html`.
- `secret-trail.js`: a bounded canvas trail of code glyphs on the secret page only. Mouse/pen movement leaves fading characters and small drifting sparks. The native cursor and links stay usable; rendering stops after the trail fades, on hidden pages, and for reduced motion or touch-only devices. Pointer coordinates remain in memory and are never stored or transmitted.
- `vendor/`: pinned local browser libraries and attribution.

Motion follows the operating system's reduced-motion preference. Project links and content remain available without JavaScript. Icon providers remain external and are disclosed in the privacy notice.

## Images and sharing

Project cards use responsive WebP previews with explicit dimensions. `data-detail-src` points to the larger image used in project dialogs; update both variants when replacing a screenshot. Original source images remain available in `images/`. The original DM mark is served as a small 64px favicon. Social metadata uses an absolute public image URL, dimensions, and a canonical portfolio URL.

## Privacy and consent

- `privacy.js` is the only Analytics loader. The main, secret, 404, and privacy pages never request Google Analytics before an explicit opt-in. Both acceptance and rejection are remembered in `portfolio-cookie-consent` local storage for 180 days. Unavailable or invalid storage defaults to analytics off.
- The footer's Cookie settings control reopens the same equal-choice panel. Withdrawal disables the tag, removes accessible `_ga`, `_ga_*`, `_gid`, and `_gat*` cookies, and reloads the page to remove loaded listeners. Choices synchronize across tabs and are rechecked on back/forward-cache restoration.
- Google signals and advertising-personalization signals are disabled. Analytics cookies request a fixed 180-day lifetime. These options do not replace checking the Google Analytics account's own advertising/linking and data-sharing settings.
- `privacy.html` explains the site operator, contact, purposes, legal bases, hosting/CDN providers, optional analytics, browser storage, email, transfers, and visitor rights. `privacy.css` styles the shared consent panel and legal pages without external dependencies.
- **Analytics retention confirmed by the owner on 21 October 2026:** Event data: 14 months; user data: 2 months; reset on new user activity: enabled. These account settings are reflected in `privacy.html` and are separate from cookie expiry and standard aggregate report retention. Update the notice if the account settings, providers, or processing change.
